# Install Telemetry

Newsjack logs a small install-funnel event when an installer-style request hits
`newsjack.sh`. The goal is to measure whether launch traffic turns into real
installs, not to identify individual users.

## What Is Collected

For `curl_hit`, the site stores:

| Field | Notes |
| --- | --- |
| `event_type` | `curl_hit` today. `install_started`, `install_completed`, and `install_failed` are reserved for later. |
| `created_at` | Server timestamp. |
| `ip_hash` | SHA-256 of IP plus `NEWSJACK_IP_HASH_SALT` plus the UTC date. Raw IPs are not stored. |
| `country`, `region` | Vercel geolocation headers. |
| `user_agent` | Raw installer user agent, used to distinguish curl, wget, HTTPie, and similar tools. |
| `referer`, `accept_language` | Request headers, when present. |
| `query_params` | Full query string, including UTMs and future tracking params. |
| `installer_kind` | Parsed installer family such as `curl`, `wget`, or `httpie`. |
| `metadata` | Operational context such as path, method, host, and Vercel request id. |

The site does not store raw IP addresses. Query strings can carry personal data
if someone puts it there, so do not add email addresses or names to launch URLs.

## Storage

Use Cloud Postgres. Default to Neon unless an existing Newsjack-owned Postgres
database is already available.

Required env vars:

| Variable | Notes |
| --- | --- |
| `NEWSJACK_DATABASE_URL` | Neon or existing Postgres connection string. |
| `NEWSJACK_IP_HASH_SALT` | Secret salt for IP hashing. The UTC date is appended automatically for same-day dedupe. Rotate the secret periodically. |
| `NEWSJACK_INSTALL_EVENT_SECRET` | Shared secret for install callback events. |

Migration:

```bash
psql "$NEWSJACK_DATABASE_URL" -f apps/site/db/migrations/0001_install_events.sql
```

Stats:

```bash
NEWSJACK_DATABASE_URL="..." node scripts/funnel-stats.mjs
```

## Stage 2/3 Callback Scaffold

`POST /api/install-event` accepts:

```json
{
  "event_type": "install_started",
  "install_id": "00000000-0000-4000-8000-000000000000",
  "metadata": {}
}
```

Authenticate with either:

```text
Authorization: Bearer $NEWSJACK_INSTALL_EVENT_SECRET
```

or:

```text
x-newsjack-install-event-secret: $NEWSJACK_INSTALL_EVENT_SECRET
```

This PR does not call the endpoint from `install.sh`. That follow-up needs an
explicit install id handoff. The current response includes
`X-Newsjack-Install-Id`, but plain `curl -fsSL newsjack.sh | bash` does not
expose response headers to the shell script. The next PR should either embed the
id into the served script body or use another explicit handoff.

## Retention

Keep raw install event rows for 90 days, then delete or aggregate them. There is
no automated retention job in this PR. Manual cleanup:

```sql
DELETE FROM install_events
WHERE created_at < now() - interval '90 days';
```

## Opt Out

The initial `curl_hit` is generated by the HTTP request to `newsjack.sh`, before
the shell has any chance to send environment variables. `NEWSJACK_NO_TELEMETRY=1`
therefore cannot suppress that first server-side hit.

When stage 2/3 callbacks are wired, the installer must skip those callbacks when
`NEWSJACK_NO_TELEMETRY=1` is set:

```bash
curl -fsSL newsjack.sh | NEWSJACK_NO_TELEMETRY=1 bash
```

Users who want to avoid the `newsjack.sh` request entirely can install from npm
or inspect and run the GitHub-hosted installer manually.
